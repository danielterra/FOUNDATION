# Ontology SQL Migration Plan

Replace 104 TTL files with a single versioned `core-ontology/ontology.sql`, embedded in the
binary at compile time. Startup goes from "parse + checksum 104 files" to "execute one SQL file
on first init only."

---

## Problem

- 104 TTL files in `core-ontology/` bundled as runtime resources and parsed on every startup
- `rio_turtle`/`rio_xml`/`rio_api` are heavy dependencies only used for this one purpose
- No clear contract for what constitutes "core ontology" vs. user data
- All IRIs use `foundation:` prefix — can't distinguish core from user data by IRI alone

## Solution

**Discriminator by OWL type + explicit registry:**

| What | How to identify |
|---|---|
| Classes | `rdf:type` ∈ `{owl:Class, rdfs:Class}` |
| Properties | `rdf:type` ∈ `{owl:ObjectProperty, owl:DatatypeProperty, owl:AnnotationProperty, rdf:Property}` |
| Default individuals | Linked from `foundation:CoreOntologyRegistry` via `foundation:includesIndividual` |

`foundation:CoreOntologyRegistry` is a singleton individual that acts as explicit registry for core
individuals. Adding a new core individual going forward = link it to the registry.

**Initial migration:** auto-populate the registry with all individuals from origins
`foundation:ontology:*` and `core` that are not classes/properties (~2,964 subjects).

## Script: `dump-ontology.sh`

### Inputs
- `~/Documents/Foundation/FOUNDATION.db` (user's live database)
- `FOUNDATION_DB` env var to override path

### Output
- `core-ontology/ontology.sql` (always overwritten)

### Algorithm

**Step 1 — Bootstrap registry (first run only)**

If `foundation:CoreOntologyRegistry` has no triples in the DB, populate it:

```sql
BEGIN;

-- Mark registry as named individual
INSERT OR IGNORE INTO triples
  (subject, predicate, object, object_type, tx, origin_id, retracted, created_at)
SELECT 'foundation:CoreOntologyRegistry', 'rdf:type', 'owl:NamedIndividual', 'iri',
       1, id, 0, 0
FROM origins WHERE name = 'core' LIMIT 1;

-- Link all TTL individuals (not classes/properties)
INSERT OR IGNORE INTO triples
  (subject, predicate, object, object_type, tx, origin_id, retracted, created_at)
SELECT DISTINCT
  'foundation:CoreOntologyRegistry', 'foundation:includesIndividual', t.subject, 'iri',
  1, o.id, 0, 0
FROM triples t
JOIN origins o ON t.origin_id = o.id
WHERE t.retracted = 0
  AND t.predicate = 'rdf:type'
  AND (o.name LIKE 'foundation:ontology:%' OR o.name = 'core')
  AND t.object NOT IN (
    'owl:Class','rdfs:Class','owl:ObjectProperty','owl:DatatypeProperty',
    'owl:AnnotationProperty','rdf:Property','owl:Ontology','owl:NamedIndividual'
  )
  AND t.subject NOT LIKE '_:%';

COMMIT;
```

**Step 2 — Collect subjects**

```sql
-- Classes + properties (schema types, any origin)
SELECT DISTINCT subject FROM triples
WHERE retracted = 0
  AND predicate = 'rdf:type'
  AND object IN ('owl:Class','rdfs:Class','owl:ObjectProperty','owl:DatatypeProperty',
                 'owl:AnnotationProperty','rdf:Property')

UNION

-- Core individuals (registered explicitly)
SELECT DISTINCT object FROM triples
WHERE retracted = 0
  AND subject = 'foundation:CoreOntologyRegistry'
  AND predicate = 'foundation:includesIndividual'

UNION

SELECT 'foundation:CoreOntologyRegistry'
```

**Step 3 — Generate SQL**

The generated file structure:
```sql
BEGIN;

-- Origins (normalized sequential IDs starting at 100 to avoid conflict with schema.sql)
INSERT OR IGNORE INTO origins (id, name, description) VALUES (...);
...

-- Single transaction for all ontology data
INSERT OR IGNORE INTO transactions (tx, origin, created_at) VALUES (1, 'ontology-import', 0);

-- Triples (tx=1, origin_id = normalized)
INSERT OR IGNORE INTO triples (...) VALUES (...);
...

COMMIT;
```

`INSERT OR IGNORE` throughout so the SQL is safe to re-run (idempotent).

## Script: `verify-ontology-dump.sh`

### What it checks

Full bidirectional integrity scan:

1. **Create temp DB** from `db/schema.sql` + `core-ontology/ontology.sql`
2. **For each core subject** (classes + properties + registry individuals):
   - Query all non-retracted triples for that subject in the **original DB**
   - Query all non-retracted triples for that subject in the **temp DB**
   - Compare: `diff <(original) <(temp)` → fail if any difference
3. **Inverse check**: every triple in the temp DB must exist in the original DB
4. **Summary**: report pass/fail + counts

### Canonical query per subject

```sql
SELECT subject, predicate,
       COALESCE(object, ''),
       COALESCE(object_value, ''),
       COALESCE(object_datatype, ''),
       COALESCE(object_language, ''),
       object_type
FROM triples
WHERE subject = '<IRI>' AND retracted = 0
ORDER BY predicate, object, object_value
```

This is deterministic (ordered) and covers all triple forms (IRI, literal, blank).

### Exit codes
- `0` — perfect match
- `1` — differences found (printed to stdout)
- `2` — setup error (DB not found, schema error, etc.)

## Rust: `connection.rs` changes

**Remove:**
```rust
const RDF_CORE_TTL: &str = include_str!("../../../core-ontology/rdf-rdfs-owl-core.ttl");
const DTYPE_TTL: &str = include_str!("../../../core-ontology/dtype.ttl");
fn import_rdf_core(...) -> ...
fn import_dtype(...) -> ...
```

**Add:**
```rust
const ONTOLOGY_SQL: &str = include_str!("../../../core-ontology/ontology.sql");

fn import_ontology_sql(conn: &Connection) -> Result<(), DbError> {
    conn.execute_batch(ONTOLOGY_SQL)?;
    Ok(())
}
```

**New `initialize_db_with_progress` flow:**
```
if new DB:
    create_schema(conn)
    import_ontology_sql(conn)      ← replaces rdf_core + dtype + all TTLs
    update metadata ontology_imported = true
    emit import-complete

if existing DB:
    open connection
    emit import-complete           ← no TTL check, no reimport
```

Remove the entire "check for modified ontology files" branch — obsolete with SQL approach.
